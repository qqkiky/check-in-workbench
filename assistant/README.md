# 微信日程助手（免费套餐第一版，尚需部署和真机验收）

处理单次日程的标题、日期时间、时长、状态，以及用户主动发给微信的待入账内容。
微信早报另同步习惯重复规则和当天完成日期，以及未定时间待办的必要字段；不包含任务备注或账本。
完整账本、账户列表、工作台中的描述和私人笔记不上传。
微信文本由腾讯通道处理，复杂日程可发送给 Cloudflare Workers AI。D1 中保存的是加密状态，
但服务运行时需要解密日程；这不是对云服务商不可见的端到端加密。

## 部署前提

1. 本地 Node.js 22+，使用 Cloudflare Wrangler 官方工具登录你自己的账号。
2. 创建 D1 数据库 `checkin-schedules`，将 ID 填入 `wrangler.jsonc`。
3. 执行 `schema.sql` 建表。
4. 分别生成随机的 `ADMIN_TOKEN`、`DEVICE_TOKEN`（至少 32 字节）和 `STORAGE_KEY`（32 字节，Base64）。
   三者通过 `wrangler secret put` 存入 Workers Secrets，不能写入配置、日志或 GitHub。
5. 首次部署后，通过管理密钥请求 `/admin/weixin/start`，用自己微信扫码，再轮询 `/admin/weixin/poll`。
   登录凭据仅留在加密状态，API 不向手机返回微信令牌。
6. APK「更多 → 微信日程助手」只填服务地址和 **DEVICE_TOKEN**，不要填管理密钥。

```text
npx wrangler login
npx wrangler d1 create checkin-schedules
npx wrangler d1 execute checkin-schedules --remote --file=schema.sql
npx wrangler secret put ADMIN_TOKEN
npx wrangler secret put DEVICE_TOKEN
npx wrangler secret put STORAGE_KEY
npx wrangler deploy
```

命令在本目录运行；部署前核实账号仍为免费套餐。真实 token 不要发送到聊天或公共仓库。

## 行为和边界

- APK 底部“助手”提供独立的本机 AI 聊天入口：在“API 设置”填写自己的服务地址、API Key、模型名。
  采用 OpenAI 兼容 Chat Completions 工具调用；提供 DeepSeek、豆包/火山方舟、OpenAI 和自定义地址预填。
  API 直接由手机 HTTPS 调用，不经过微信或本项目的 Cloudflare 服务；密钥和对话使用现有 Android 私有加密存储，
  不随备份或设备同步导出。服务商可处理用户主动发送的对话及已给出的操作参数；完整账本不上传，
  查账、余额和笔记检索结果仅在本机显示。模型另接收匹配所需的待办标题、日期时间及完成状态，不含任务备注；查账、余额和笔记查询结果不进入模型上下文。
  本地操作覆盖日程的增改查、完成恢复和删除；记账的增改查删；账户的增改查删；笔记的增改查删和账户间转账。
  金额、账户和日期须通过本地校验；模糊多项时追问；删除必须点击本机确认，已有账目的账户不允许由助手删除。
  日程操作写入本机后尝试立即更新系统日历，权限不足会明确显示，不能保证模型或网络每次几秒响应。
  此入口需要 APK 打开；不等于微信锁屏秒级同步。输入区可切到“语音”，按住说话、松开后自动转写并发给 AI，
  上滑或离开页面会取消；单次最长60秒。首次允许麦克风后需重新按住。只使用系统识别的最终结果，不发送失败或取消的语音。
  系统语音服务可能联网，需设备提供可用的中文识别服务；应用不保存原始音频，也不把音频发给聊天 API。
  下拉控制中心编辑快捷按钮，添加“期待对话”。点击后直接进入助手的语音输入界面，仍需按住说话才开始识别。
  首页区分下一项、逾期、其他待办、待安排和折叠的已完成；周期习惯沿用分类浅底色，临时事项白底。
  折叠的已完成只按所查看日期的实际完成时间筛选，历史打卡记录继续保留。
  Android 使用标准输入连接（关闭 captureInput）；同步刷新不重置已打开表单的文字草稿。
  APK 不注册网页离线 Service Worker，打开时注销旧注册；更多页显示当前包内界面版本。
  系统日历按钮同时核对双向删除、清理已删除任务的残留，并显示处理数量；返回应用时也会检查。
  日历中删除一次性日程会删除对应本机任务；删除某天的习惯只加入 excludedDates，后续习惯与历史打卡保留。
  仅核对本 APK 记录过对应关系且属于专属日历的事件；隐藏日历、权限或查询失败不视为用户删除。
  删除标记阻止后台重新创建；尚未导入的微信新日程单独保护，避免全量清理误删。
  往日未完成的一次性事项在今天继续显示，往日漏打的重复任务只在其所属日期查看，未定时间事项不标逾期。
  外屏按实际可用宽高切换三入口布局；日期和日/周/小事从日历按钮进入，记账、回顾和资讯从“更多”进入。
  AI 的 update_completion_time 使用 completedTime/completedDate 更正实际完成时刻，date 定位原任务实例；保留记录编号、计划和完成状态。
  首次完成也支持实际完成时间；时间早于已有开始时间、晚于现在或记录不明确时不修改。只有明确撤销完成才允许恢复待办。
  冷启动和后台唤起都处理同一入口；锁屏时先由系统解锁，不在锁屏展示对话。快捷按钮不依赖后台常驻或悬浮窗权限。
  语音转写后走相同的本机校验、待办保存和日历同步流程，信息不全或多项匹配时继续追问。
  外屏加入 Android 小封面屏声明、小米连续性与贴边显示声明；左右安全区域避开侧边摄像头。
  更新后在系统“设置 → 外屏 → 应用管理”检查是否可添加，是否列出仍由设备系统策略决定，不能仅凭模拟窗口测试保证。
  适配依据：[Android 语音识别](https://developer.android.com/reference/android/speech/SpeechRecognizer)、
  [小米 Flip 适配](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2026)。
  实现依据：[OpenAI 工具调用](https://developers.openai.com/api/docs/guides/function-calling)、
  [DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、
  [火山方舟兼容接口](https://console.volcengine.com/ark/region:cn-beijing/docs/compatible-with-openai-sdk)。

- APK 自动加密保存本机数据，不再启用旧 Supabase 同步或显示 PWA 安装提示。
  “数据同步”按钮在设备端用用户自己的随机32字节密钥进行 AES-GCM 加密；云端只存密文，
  不持有此数据密钥。同步全部业务数据及偏好，但排除连接凭据、旧 Supabase 参数和本机授权状态。
  不同设备新增记录合并；相同记录或删除与修改冲突时，由用户逐条选择。
  云端使用版本条件写入，拒绝过期上传；错误密钥不覆盖任何数据。
  首次接入可由管理端 `/admin/device-pair` 生成8位连接码，通过公开 `/v1/device-pair` 兑换设备凭据；
  连接码10分钟有效、仅能使用一次、最多尝试10次。数据加密密钥始终在设备生成和保管。
  已连接设备也可通过鉴权接口 `/v1/device-code` 生成其他设备的连接码，无需电脑在线。
  单次业务数据上限512KiB；手动 JSON 备份仍为明文。忘记数据密钥后，云端不能帮助解密。

- 日程助手会整理口语重复和自我纠正：信息齐全自动创建，缺少标题、日期或具体时间时继续追问。
  只暂存尚未补齐的结构化日程和上一条追问，24小时后清理，不保存完整对话历史。
  可回复“取消整理”放弃草稿；多项日程分别处理。AI 额度与微信语音转写限制仍然适用。
  支持分条补发纠正标题和时间；对话中最近唯一创建、修改或完成的日程保留15分钟的ID引用，完成后仍可明确纠正为未完成；
  明确的纠正直接更新原日程并回复最终标题与时间，不重复创建、不额外确认。明确说“我搞错了，其实这件事没做完”会恢复刚才事项为未完成，保留原计划；仅更正完成时间不得撤销完成。目标不明或多条同名时追问。
  管理端 `/admin/interpret` 可用虚构消息预览整理结果，不写入日程；仍计入免费解析次数。

- 微信记账示例：“微信，午饭支出30元”“支付宝收入工资5000元”。
  缺少账户、金额或收支类型时追问；可回复“账户：APK 中的完整账户名”“支出30元”。
  原生语音采用腾讯通道提供的转写文字，支持“三十元”等中文金额；若通道没有提供转写，明确提示补发文字。
  不下载录音，不添加其他语音服务，不读取支付通知，不做分类学习。
- 记账只匹配手机中的完整账户名，不猜默认账户、不自动创建账户；不存在或重名时继续追问。
  收支先归入本机的“其他支出”或“其他收入”，可在 APK 修改。微信支持主动发送的账户转账及信用卡还款，例如“用工资卡还招行信用卡1200元”；仅记录账本并更新余额，不实际划款，也不重复算作消费支出。缺金额或任一账户时分步追问，不能根据欠款余额猜金额。账户仍只在手机精确匹配，云端不获取账户列表。借款、退款等未支持的账务仍在 APK 操作。
  默认今天，支持昨天、前天或 YYYY-MM-DD；账目未指定具体时间时记在当日12:00，不声称真实支付时刻。
- 待入账记录和未补齐草稿在云端加密暂存最多7天（定时任务及访问时清理）。
  打开 APK 后自动接收，应用关闭时保持“待同步”，现有日历后台任务不会写入账本。
  手机加密保存成功后才发送仅包含消息ID、版本及处理状态的回执；断网重试不重复入账。
  收到回执后从当前云端状态移除该笔待入账记录；这不代表删除腾讯聊天记录或云服务商备份。
  完整账本及账户列表始终不发给助手云端，查账在 APK 记账页进行。

- 每分钟检查微信消息，采用腾讯官方公开的 iLink 协议；未完成真实账号扫码测试前不算可用。
- 明确格式“明天下午3点写报告”“写报告完成了”“今天的安排”可走本地规则，免费 AI 每天最多 30 次请求。
- AI 不能直接访问数据库或执行命令；其输出必须通过日程字段校验。时间不明确或多项同名时会追问。
- 微信消息可能受会话有效期限制，失败仅记录状态，不假报送达。
- 日报默认 08:00，跟进默认 30 分钟，当天每项最多 8 次，22:00–08:00 不催办。
  日报和“今天的安排”查询只列当天未完成事项，包括日/周/月习惯及未定时间待办，不带入逾期事项。
  安装更新后需打开 APK 同步一次习惯规则；云端会独立按日期筛选，无需每天打开电脑重新生成。
  “同步清单到微信助手”更新微信清单，“与小米日历同步”核对手机日历，两者分别报告结果。
- “小爱日历导入”需在手机选择小爱写入的日历，仅导入今天及以后的单次日程（含全天），暂不导入系统重复日程。
  日历与期待中的标题/时间修改回写原日历和原事件编号，不搬移来源日历，不覆盖来源备注。
  使用日历变更监听及启动/返回应用时核对；进程被系统结束后，下次打开补齐，不承诺关闭应用时秒级同步。
  新导入关联先保留接收状态，手机业务数据加密保存失败时不会将来源日程当成残留删除。
  日历对账签名仅存哈希；关闭原生调试日志，文件读写共用锁并核验原子写入结果。
- 手机上前台/联网恢复时自动同步；APK 后台通过 WorkManager 约 15 分钟或更长间隔刷新专属日历。
  系统省电、断网、强制停止应用都会延迟。暂不提供秒级或必达承诺。
- APK 保存完整数据时使用 AndroidKeyStore + AES-GCM；日历和系统通知不是加密存储。
  日历事件标题会显示任务内容，可能出现在锁屏，需自行设置锁屏通知隐藏内容。
- 用户手动导出的 JSON 仍为明文备份，须自行妥善保存；令牌和助手配置不导出。
- 密钥丢失、卸载 APK 或清空应用可能无法恢复加密数据；先做手动备份。
- 之前启用 Supabase 上传的旧数据不会因本次收窄同步范围自动从服务器消失，需要另行检查。

## 验收清单

1. 先用虚构日程测试，不导入真实私人数据。
2. 微信创建两项任务，APK 和专属日历各出现一次。
3. 微信完成其中一项，APK 勾选；日历标题出现“✅ 已完成｜”，无后续提醒。
4. 同名任务时明确追问，不同时完成多个任务。
5. APK 修改/完成状态不会被旧云端数据覆盖；断网时本地工作可继续。
6. 检查云端请求中没有记账、私人笔记、任务描述、账号配置和其他聊天内容。
7. 手机锁屏和重启后，确认日历提醒、后台刷新及授权状态；小米需允许后台活动。
8. 微信发“午饭支出30元”，追问账户；补齐后先显示待同步。打开 APK 后恰好入账一次，收到确认后云端队列为空。
9. 断网重试、账户重名或不存在时不猜账户、不重复入账；抓包确认回执没有账本、账户列表或余额。

预览 APK 使用 `.preview` 包名与临时调试签名，仅供测试。正式发布须使用你自己保存的固定签名密钥，
不能拿预览包替代正式版本。此分支未合并上线前，原 PWA 继续使用原版本。

交给用户安装的后续预览包须在本机使用 `assistant/.wrangler/signing/checkin-preview.jks`
重新签名，密码存于同目录的 Windows DPAPI 文件；密钥和密码不得提交 GitHub。
GitHub 构建产物仍使用临时调试签名，不能直接作为用户更新包。
从旧的临时签名测试包迁移到固定签名时，必须先确认用户数据已备份，再手动重装；不要自动卸载或清空数据。

## v15 对话、解绑与提醒核对

- 内置 AI 使用最多200项必要待办元数据进行语义匹配，简称或近义表达不必逐字一致；多个合理候选仍追问。当前对话里的“这件事”结合明确操作的ID处理，日期改期保留未要求变更的时间。重复习惯只移动指定那一次。
- 成功操作后可追加一次不带工具的 API 请求生成简短自然回复；回复生成失败不会重跑操作。API 费用仍由用户所选服务商计算。
- 微信端同样用候选ID匹配；习惯和未定时间待办的操作通过带原快照的接收队列保存到手机。手机存在并发修改时拒绝覆盖并返回冲突；手机接收前明确显示等待同步。
- 收到官方通道的失效登录返回（-14或HTTP401）后清理连接凭据及旧发送队列，保留业务日程、加密全量数据及待入账记录。暂时网络失败不视为解绑。接口连接状态不再只根据旧令牌是否存在判断。
- “暂停微信提醒与手机同步”会暂停云端早报和催办；“解除微信连接并停止提醒”停止云端通道并清除旧队列。重新扫码后保持提醒暂停，必须在手机成功同步最新清单后再恢复。
- 每条催办绑定任务版本，发送前重新读取当前状态。改名、改期、完成或暂停后的旧催办不会继续发送；积压的早报在送出前重新计算当天清单。
- 微信里记录的还款沿用最多7天加密暂存、手机持久化成功才确认、成功后删除云端待同步记录的流程。重复拉取和回执丢失不重复入账，全部账本和账户列表仍留在手机。

微信消息先识别当前待办的明确完成或纠正指令，再处理记账关键词。例如“今天的记账做完了”“把记账这件事勾选”只完成相应待办；明确金额、收支或转账信息仍进入账务流程。补充“只勾选任务”后会清理此前由完成语句误建且没有任何金额、账户或收支字段的空草稿；真实的待补齐账目保留。也支持“不记上一笔了”等自然取消草稿表述，不会取消日程或改动手机已入账数据。

纠正完成状态支持省略主语的口语，例如“搞错了，其实这件事没做完”“说错了，这件事其实没做完”。有有效的最近任务关联时直接恢复该项，保留原日期和时间；手机接收并回传完成状态后仍保留此关联。无有效关联、超过15分钟或明确提到其他事项时不猜测目标。

## v17 手机完成状态自动上传

勾选或恢复任务后300毫秒触发同步；同步中发生的任务或记录变动会排入下一轮，不因忙碌丢失。切换到微信时立即提交尚未执行的同步；相同内容的存储重读不反复触发同步。微信清单及任务回执先于记账接收和日历核对，后两者失败不会阻止已完成状态上传。断网、系统结束进程或限制后台时仍可能延迟，重新联网或打开期待后补同步。
